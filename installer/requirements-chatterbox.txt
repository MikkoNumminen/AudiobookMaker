# Canonical pinned dependency set for the Chatterbox TTS engine venv.
#
# WHY THIS FILE EXISTS
# --------------------
# The Chatterbox engine venv must be REPRODUCIBLE. Pinning only the top
# package (chatterbox-tts) and letting its dependency tree float lets pip
# resolve whatever is latest/cached on the user's machine at install time.
# When pip lands a `transformers` newer than the validated one, the
# (older, pinned) chatterbox-tts calls a changed/removed transformers API
# and the load fails at runtime with the cryptic, generic error:
#
#     Could not import module 'LlamaModel'. Are this object's
#     requirements defined correctly?
#
# That message is the transformers `_LazyModule` wrapper hiding the real
# version-mismatch failure. It only fires when the model loads — never at
# install — so a broken venv ships silently. Pinning the whole runtime
# chain closes that hole: every install resolves to the same versions, and
# a plain reinstall force-downgrades an already-drifted venv back to these
# exact pins.
#
# SINGLE SOURCE OF TRUTH
# ----------------------
# Both install paths must install exactly this set:
#   * the in-app "Install engines" button  -> src/engine_installer.py
#   * the Inno Setup wizard post-install    -> installer/post_install_chatterbox.py
# A parity test (tests/test_chatterbox_requirements.py) asserts this file
# and both installers' PIP_PACKAGES_MAIN lists stay identical, so they can
# never drift apart again.
#
# BUMP POLICY
# -----------
# Raising ANY pin here requires, in order:
#   1. A successful end-to-end smoke synth on the new versions.
#   2. Refresh the dev freeze (pip freeze of the working venv).
#   3. Update this file AND both PIP_PACKAGES_MAIN lists in the same change.
#
# torch / torchaudio are deliberately NOT in this file. They install
# separately via the CUDA wheel index (--index-url) so chatterbox-tts's
# resolver treats torch as already satisfied and does not pull the CPU
# wheel. See TORCH_WHEEL_VERSION / TORCH_CUDA_INDEX in both installers.
